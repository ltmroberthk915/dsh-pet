# v1.3.1 动画稳定性修复

修复 v1.3.0 实装后鲸鱼娘抖动、小蓝鲸明暗闪动和高速生成时动作过快的问题。

- 原画与独立生成的补帧在比例、线条和光照上不一致，不再交替播放。鲸鱼娘站立动作使用原画，跑步使用同一组新画稿；小蓝鲸站立动作使用原画，游泳保留完整的一组八帧。MIKU 回到原始动作帧。
- 图像文件保持原像素。`sprite2d.tracks.*.frames` 明确指定要播放的图集列，列号必须在该行范围内。
- 鲸鱼娘待机停留 4.6 秒后进行一次短眨眼；等待和检查动作延长停留。小蓝鲸使用舒缓的四帧待机节奏。
- 当前鲸鱼娘与小蓝鲸使用整帧、整数显示像素的位置校准，取消逐帧缩放和腿部拼接。跳跃与鞠躬保留主动动作的高度变化。
- 三种内置形象跑步、游泳最高 12 FPS；当前有效帧密度为 1。设置预览显示限速后的实际目标。通用播放器补帧后也不再超过 60 FPS。
- 修复 32 列鲸鱼娘误用旧 8 列眨眼替换表的问题。
- 独立窗口运行库改存到 DSH 数据目录的 `cache/pet-desktop`，避免从 Windows Store 应用启动时 AppData 文件重定向导致路径校验失败；文件边界与哈希校验继续保留。

重建时，在旧素材构建流程之后运行 `node scripts/configure-calm-motion.mjs`，再运行 `python scripts/measure-companion-registration.py`。后者只读取图像、测量位移并生成坐标表，不改写图像。重新构建客户端后需要重新封装桌面校验清单。

原生测试使用生产桌宠窗口，检查整张待机画面静止、297 tok/s 时的实际帧变更次数、九种动作、五套配色、完整身体以及长按拖动。历史 v1.3.0 的“腿部像素相同”不足以证明全身稳定，因此本版取消了该断言，改为整张待机画面像素对比。
