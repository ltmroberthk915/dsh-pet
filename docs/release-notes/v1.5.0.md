# 1.5.0 · 全包更名与应用内「专属宠物保持」

- **包名更名**：`dsh-pet-copilot` → **`dsh-pets-multiworkers`**。npm 包名、客户端模块 id、桌面桥清单、安装器路径与文档统一更换。插件行 id 仍为 `pet`，`pet.json` 数据目录、设置命名空间与宠物养成数据不变。
- **新增会话右键菜单「专属宠物保持」**：在侧栏具体会话的 `...` 菜单中选择后，该会话所属主代理宠物在结果已查看、焦点切走时不再被回收；它仍按现有规则随焦点会话切换主/次大小（52.7%），该会话的子代理宠物继续按原有逻辑显示与隐藏。再次选择「取消专属宠物保持」恢复原回收规则。
- 即使该会话当前没有实时活动记录（例如宿主重启后变冷，或设置保持时并未在运行），也会按该会话自己的配色合成一只常驻空闲宠物：聚焦它时用主大小，其他时用次大小；会话被删除时保持标记自动清除，不留幽灵宠物。
- 保持状态持久化到 `pet.json` 的 `keptSessions`（去重、单条 ≤200 字符、最多 512 条，最早条目先淘汰），DSH 重启后仍生效。
- 新增宿主接口 `GET /api/pet/kept-sessions` 与 `POST /api/pet/session-keep`；`/api/pet/state` 快照同时携带 `keptSessions`，菜单打开与轮询无需额外请求即可显示当前状态。
- 菜单行沿用 `sidebar.workspaces.session.menu.item` 槽位（与「发送消息到会话…」同一扩展点），排在 `order: 500`，位于内置「归档会话」之前；样式只使用宿主主题 token，不加载宿主客户端 UI 包。
- 新增宿主端“保持/取消保持、子代理不参与、重启后持久化、读轮询不写盘”和客户端“菜单行标签/关闭/禁用、keep store 轮询去重”测试。

## 更名迁移

DSH 同时按行 id 与 name 匹配覆盖项。只保留 `id: pet` 不足以让旧名称下的配置继续生效：

1. 备份 DSH_HOME。
2. 在目标 profile 移除 `dsh-pet-copilot`（或更早的 `@ltmroberthk915/dsh-pet`、`@linxin666/dsh-pet`），安装 `dsh-pets-multiworkers`，不要同时启用两套 bundle。
3. 运行 `scripts/migrate-profile.mjs --patch <profile>/cordis.patch.yml [--apply]`；默认只预览，加 `--apply` 才写入，并在写入前用真实宿主合成核对结果。工具会把 pet 行旧名称标量改成新名称，保留 config、disabled、注释与其他插件。

替换已加载的插件版本后，需完整退出并重开 DSH 以加载新的宿主与客户端代码；首次新增 bundle 仍可热加载。

## 验证

`pnpm typecheck && pnpm test && pnpm build`，随后 `node scripts/build-desktop-manifest.mjs` 重新生成桌面桥清单。更名后的 npm/Release 发布仍需按既有冷却与安装验收流程单独完成；本地安装包与 npm 发布结果不能互相替代。
